
Analyze the current optimized CanvasSequence.tsx.

The previous optimization improved smooth scrolling,
but a new issue remains:

PROBLEM:
When scrolling slowly, the 960-frame animation works better.
When scrolling very fast, the animation freezes on one frame
until the required frame becomes available.

My test laptop has:
- 4GB RAM
- 2nd generation Intel CPU

OBJECTIVE:
Improve fast-scroll responsiveness without sacrificing
visual quality or causing excessive memory usage.

INVESTIGATE:

1. Check whether the frame-loading queue gets overwhelmed
   during rapid scrolling.
2. Check whether outdated queued requests are still being
   processed after scroll position changes.
3. Check whether image decoding blocks urgent frame loading.
4. Check whether LRU eviction removes frames that are
   immediately needed again.
5. Check whether the renderer gets stuck waiting for a
   missing frame.
6. Check whether loading and rendering are competing
   for the main thread.

POTENTIAL IMPROVEMENTS:

- Prioritize the latest requested frame.
- Cancel or deprioritize obsolete loading requests.
- Prioritize frames around the current scroll position.
- Keep a small forward and backward frame buffer.
- Avoid decoding too many images simultaneously.
- Keep rendering responsive during fast scrolling.
- Optimize memory usage for low-RAM devices.
- Avoid displaying stale frames for too long.

IMPORTANT:

Do not blindly implement every suggestion.
First identify the actual bottleneck.

Preserve all 960 frames and original image quality.
Do not modify Lenis, scroll speed, website design,
GSAP animations or section layouts.

Do not preload all 960 frames into memory.

After implementation:
- Test fast scrolling.
- Test reverse scrolling.
- Test slow scrolling.
- Run npm run build.
- Run npx tsc --noEmit.

Report the exact changes and remaining limitations.
